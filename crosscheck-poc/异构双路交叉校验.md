# 异构双路交叉校验报告（本地 Qwen3 vs 云端 混元）

## 配置
- path-A: local-llama / qwen3-35b-a3b（本地 llama.cpp，35B MoE）
- path-B: workbuddy / hy4flash-free（云端混元）
- 输入：与同源 PoC 完全相同的报警快照 + 固定输出契约
- 前置：恢复 subagent-model-selection 白名单为双路由（见 FUSION-VERIFICATION.md）

## 第一轮：独立分析

| 维度 | 本地 Qwen3 | 云端 混元 |
|---|---|---|
| 主因 | 炉门开启单独为主因 | 炉门为主 + 装料偏多为次因 |
| 置信度 | 高 85% | 中 75% |
| 装料35% | 弱化为非主因 | 纳入为放大/次因 |
| 疑点深度 | 2条（较浅） | 4条（含定量质疑、数据缺口） |

→ 存在实质分歧（主因是否单一） → 触发规则2复核。

## 第二轮：针对性质疑复核

### 本地路复核后（被说服）
- 主因改为：炉门开启 + 装料偏多 35% 叠加，缺一不可，无法单独归因
- 置信度：高85% → 中70%
- 接受了云端质疑：12秒开门单独难造成45°C骤降

### 云端路复核后（坚守并强化）
- 结论：装料偏多不应从次因降级；置信度 75% → 高80%
- 关键论证（7条）：
  1. 语义先对齐：装料本就是次因，分歧仅在是否完全剔除
  2. 98%饱和是非特异性指标，不指示热亏缺来源
  3. 阶段错配：02:16饱和在恢复期，不能回溯否定降温期成因
  4. 反向解读：慢回温恰支持装料热容大
  5. 措辞纠错：快照是'已恢复'非'无法恢复'，只是偏慢
  6. 虚假二选一：开门触发+装料拖慢作用于不同阶段，可并存
  7. 数据缺口：缺02:14-02:15功率，若开门前已饱和反支持装料因素

## 最终裁决

**两路收敛到共识**：炉门异常开启是降温触发主因；上一批装料偏多35%是放大降幅、拖慢回温的次要/放大因素。两者作用于不同阶段，可并存。

共同保留疑点（两条路独立提出）：
1. 缺 02:14-02:15 降温窗口功率数据
2. 上一批次装料是否仍在炉内未澄清
3. 热电偶位置/分区不明（炉气整体 vs 探头局部冷风直吹）

## 核心价值实证（对比同源 PoC）

| 维度 | 同源 PoC（workbuddy x2） | 异构双路（local vs cloud） |
|---|---|---|
| 第一轮分歧 | 无，结论/疑点高度雷同 | 有，主因单一 vs 主+次 |
| 信息增量 | 仅漏项互补（B漏处置建议） | 观点碰撞→质疑→修正→逻辑纠错 |
| 结论演进 | 无 | 本地路修正归因，云端路识别对方逻辑谬误 |
| 降幻觉价值 | 低（自己审自己） | 高（真正独立意见交叉校验） |

**结论**：Linger 式'独立意见交叉校验降幻觉'在本机已实证成立。关键不在双路本身，而在两路必须是不同模型族——同源双路只是回声。

## 诚实标注
- 单一样本，机制稳定性未经统计验证
- 本地模型 35B 参数量小于云端，但推理质量在本轮不落下风（云端论证更严密属模型特性差异，非能力高低定论）
- 结论基于虚构快照，真实产线需接入真实遥测（OT网关）验证
